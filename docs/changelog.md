- 2026-09-09 — Replaced up/down-button curriculum reordering with real drag-and-drop (`@dnd-kit/core`/`sortable`/`utilities`) supporting both mouse and keyboard — the prior version was a deliberate stand-in, not the actual spec, and this corrects it rather than adding drag alongside the buttons

- 2026-09-10 — Fixed curriculum drag-and-drop jank: added `<DragOverlay>` (the dragged row was rendering via its own in-place `transform`, with no portal, so it visually overlapped content above the list) and an optimistic `onMutate` cache update on both reorder mutations (there was no client-side update at drop, so the list snapped back to the pre-drag order for the ~1s round-trip, then jumped again once the refetch landed — read as a sibling disappearing). The reorder mutation already fired only on `onDragEnd`, never per pointer-move — that half of the original bug report's hypothesis didn't hold up against the code, confirmed before touching anything
- 2026-09-10 — Recorded "reorder mutations fire on drop only, paired with DragOverlay + optimistic onMutate" as a standing pattern for the next sortable list (`rules.md`, `ui.md`) — this bug was exactly what happens when only one half of that pair is implemented
- 2026-09-10 — Removed all curriculum reorder animation (`transition: null` + `animateLayoutChanges: () => false` on `useSortable`, `dropAnimation={null}` on `<DragOverlay>`) — a deliberate product decision for an instant snap, not a bug fix; the one non-obvious case was the overlay's own `transition` prop defaulting to `'transform 250ms ease'` for keyboard-activated drags specifically, which needed an explicit `transition={() => undefined}` override since `dropAnimation={null}` alone doesn't touch it. No sub-case required a fallback or partial fix — verified zero-`transitionDuration` live via Playwright on both pointer and keyboard activation
- 2026-09-10 — Swapped the lesson create/edit editor from a slide-over Sheet to a centered Dialog (`LessonDialog.tsx` replaces `LessonSheet.tsx`) — reuses the Dialog convention already established by Admin Users' create/edit dialogs instead of the two container primitives coexisting; same trigger points, field set, and content-type branching (video direct/embed, text, game, quiz-deferred note), sized `sm:max-w-lg` with explicit `max-h-[85vh] overflow-y-auto` since base `DialogContent` has no built-in height cap
- 2026-09-12 — Lessons can now be dragged between topics and into/out of Ungrouped, landing at the exact drop position rather than being appended — previously each topic's lessons were their own `DndContext`, and dnd-kit shares no drag state across sibling contexts, so cross-topic dragging had no code path at all. Topics and lessons now share one context discriminated by `data.type`, which is forced rather than chosen: lesson rows render inside topic cards, so any context spanning all lessons is also the nearest one for the topic cards, and `useSortable` resolves through plain React context. Module reorder behaviour is unchanged
- 2026-09-12 — Recorded that `lessons.position` is per-`module_id`, not per-course, as an invariant — verified against live data (two lessons in different topics both at position 0) and against the schema, which has no unique constraint or trigger backing it; the cross-topic recompute depends on it and nothing in Postgres would catch a writer that assumed otherwise
- 2026-09-12 — Three fixes the cross-topic drag needed, each found by live verification rather than review: droppable measuring set to `Always` (moving a lesson resizes both topics mid-drag, and the default measures once at drag start, so dropping into an empty topic silently did nothing); collision detection snaps to the nearest row when the pointer is in the gap between rows (answering with the container means "append to end", so the row flicked to the bottom whenever the pointer crossed a gap); and the live draft preview is pointer-only (keyboard drags derive coordinates from the layout, so reordering under them fed back into the sensor and one ArrowDown moved two slots)
